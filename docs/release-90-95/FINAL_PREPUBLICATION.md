[Supabase Database Backups](https://supabase.com/docs/guides/platform/backups)では物理バックアップの直接ダウンロード不可を説明している。[Restore to a new project](https://supabase.com/docs/guides/platform/clone-project)では、別プロジェクトへの復元は新しいプロジェクトの月額費用が発生する。物理復元はcron/外部通信拡張も引き継ぎ、復元直後から動作し得る。

したがって、追加費用0円・本番変更禁止・既存TEST保全の条件下では次を実行しない。

- 新規Supabaseプロジェクト/branch/PITRの有効化

- 稼働中TESTへの上書き復元
- cronや外部通信を持つ物理コピーの起動

ローカルにはPostgres17.11とpg_dump/pg_restoreがある。公式CLIのdumpコマンドはdry-runだけ確認したが、これは既存の物理バックアップをダウンロード/復元した証拠ではない。新しく作る論理dumpやschema-only復元を、既存物理バックアップの復元成功に置き換えて報告しない。実バックアップの復元可能性は未実証のまま保留する。
