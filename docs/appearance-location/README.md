# 出演予定の概略位置と出演者による位置確認

基点: main 850424a5e3efdb17d7a9506a840288d4aeeb9955（#101公開済み）。本番DB変更・既存データ補完・migration追加なし。位置解決はブラウザの表示時だけに行い、venue_lat/venue_lngへ保存しない。

## 判定と表示

- 有効な登録済み座標を最優先。片側のみ/範囲外/NaNの座標がある場合は推測で代替しない。
- 座標が両方未登録なら、下の審査済み代表地点だけを使う。日本以外・地域/住所に矛盾がある・名前を特定できない予定は位置を作らない。名称のあいまいな部分一致はしない。登録後に会場名等が変わっても、その都度再判定する。
- 「概略位置」をマーカー・選択シート・近隣一覧に明記。地域/住所代表点であり、実際の出演地点とは異なる。近隣距離も概略として表示。
- 近隣一覧で予定を選ぶと該当地点へ移動する（概略は広めの縮尺）。GPS拒否/利用不可かつ既存LIVE/会場/共有位置がない時は代表地点へ初期移動し、世界地図の画面外に放置しない。定期更新のたびに利用者の手動パンを戻さない。
- 概略位置のGoogle Maps導線は元の会場名/住所/地域を検索する。代表座標を正確な出演地点の経路として渡さない。登録座標がある場合だけ座標による経路案内を利用する。
- 公開中の未来予定、または開始を含み終了を含まない時間帯だけMAP対象。非公開・中止・延期・archived・過去・無効日時は対象外。終了未登録の予定は開始後に表示を続けない（既存APIの取得条件と整合）。LIVEマーカー/配信判定/位置の処理は変更しない。

## 新規登録・費用

会場名・住所・地域・任意の座標を入力できる。位置の地図確認は明示的に開いた時だけ、Leaflet 1.9.4とOpenStreetMap標準タイルを使う。地図上の選択/中央選択→確認チェック→「この位置を使う」で初めてフォームへ座標を設定し、予定の保存時だけ本人操作の座標を保存。表示用代表点を自動確定しない。現在地APIは使わない。

会場名/住所/地域/国の変更時は古い座標をクリアして再確認を案内。未特定・片側のみ・範囲外なら有効な座標ペアを保存せず、位置なしでも予定登録を継続できる。地図読込失敗や未確認でも元の登録を妨げない。

Google Mapsの新しいキーや有料Geocoding API、住所のバックグラウンド検索は導入しない。新規契約・有料リソースなし。既存HAKU MAPのGoogle Maps設定は変更しない。

OpenStreetMapタイルは明示操作で必要な表示範囲だけ取得し、ブラウザキャッシュを尊重。Refererと©OpenStreetMap contributorsを表示。prefetch/一括取得/オフラインタイル保存は行わない。公共サーバーにSLAはなく、停止・制限時は地図入力が使えない場合がある（位置なしの登録・Google Maps検索は継続可能）。
- 利用条件 https://operations.osmfoundation.org/policies/tiles/
- Leaflet公式 https://leafletjs.com/examples/quick-start/

## 検証境界

Vitestで既存4種/正確座標優先/矛盾・未知・不正座標/時間・公開状態/検索リンク/距離を確認。WebKitでは既存の登録→一覧→MAP→共有・LIVE保全に加え、概略ラベル、DBに相当するfixtureへ座標を書かないこと、地図確認→登録座標優先、位置不明でも登録できることを検証。API・Google Maps SDK・OpenStreetMapタイル・OS共有はfixtureであり、実OSや外部地図サービスの成功とは区別する。E2Eは外部タイルをダウンロードしない。

物理iPhoneでは、概略ラベル/近隣の目安表示、地図タップ/スクロール/確認、Google Maps検索/経路の受渡し、圏外時も予定を保存できることの確認が必要。本番データを無断登録/変更しない。
