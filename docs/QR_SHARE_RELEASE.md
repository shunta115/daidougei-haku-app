# QR保存・印刷・SNS共有の独立リリース

基点: main `398d05b9c51ed84ed0b1a3bb1c7beae62a52f616`。引継元: PR #101 `6c5eadd`。ブランチ: `codex/qr-share-only`。

## 範囲と依存監査

QRのPNG保存・プロフィール共有はmainの既存実装を維持。追加はA4印刷カードと公開予定のLINE/X/共有シート/URLコピー。SNSボタンは独立した表示部品へ切り出し、予定一覧への差分はimportと部品配置の2行のみ。

- DB migration、SQL、DBアクセス層、API route、型定義、MAP座標/マーカー処理、通知RPC、登録/複製/複数日登録、決済/LIVEの変更なし。
- `api/`、`server/`、`shared/`、`supabase/`、`src/platform/lib/api.ts`、`types.ts`、`GoogleVenueMap.tsx`はmainとの差分なし。
- 新しい会場座標列や当日通知RPCを要求しない。main既存の公開プロフィール/予定データを利用する。DB読み取りが一切不要という意味ではない。
- 旧event-slot互換予定は存在しないappearance IDへ誘導せず、既存のプロフィール予定表へ共有する。
- 共有先は公開URLだけ。認証値は含めない。共有キャンセルとClipboard拒否を処理し、失敗表示を用意した。

## 物理iPhone: 最小3項目

1. 公開プロフィールのQRを保存し、写真/ファイルで実物を開く。
2. PrintからA4の印刷プレビューを開き、1ページに切れず表示されることを確認。PDF保存でよく、実印刷は必須ではない。
3. 公開予定から共有シート・LINE・Xの作成画面を開き、予定URL/出演者/日時を確認。送信・投稿せずキャンセルする。

機種・iOS/Safari・実施日時・公開予定URL・3項目の合否だけを記録する。パスワード、トークン、連絡先は証跡に入れない。

## TESTログイン・MAP・バックアップ（このリリースのDB変更には不要）

- 既知の環境ファイルでは変数名とTEST接続先の有無だけを確認し、TEST専用認証情報は発見できなかった。秘密値を表示せず、認証緩和・パスワード変更・管理者トークンによる代替は行っていない。
- VercelのMapsキーはProduction専用。無断複製なし。APIキー不要の外部Google Mapsリンクは実表示確認済み。アプリ内MAPの実接続には既存TEST用キーのreferrer制限と無料枠残量の確認が必要。Google Cloudの課金状況は接続情報から確認できないため0円とは断定しない。
- 本番物理バックアップの新規プロジェクト復元は追加費用が発生し得るため未実施。ローカルPostgres17.11/pg_dump/pg_restoreは利用可能。既存の論理dumpが提供されれば、0700の専用ディレクトリ・Unix socketのみ・外部通信/cron停止の隔離環境でchecksum/件数/RLS/制約を検査できる。ただし、その結果は既存の物理バックアップ復元成功を証明しない。既知の作業領域に復元用dumpは見つからなかった。

## Previewと承認審査

Supabase値をPreview環境変数へ永続化する操作は、自動承認審査で「その秘密設定への承認がない」と拒否された。新しい秘密設定を書き込んでいない。秘密情報を含まない静的デモの手動作成もPreview対象の明示を理由に拒否されたため、そのAPI操作を回避して再実行していない。

独立PRは非mainブランチの通常Git連携Previewを利用し、既存Preview設定を継承する。実DB未接続の表示確認用ビルドは `vite build --config tests/qr-share-e2e/preview.config.ts` で生成可能。これは本番アプリのbuild設定を変更しない。

## 最短公開手順

1. 独立PRだけをレビューし、mainとの差分にSQL/通知/MAP/決済の変更がないことを確認。
2. 物理iPhoneの3項目を確認。
3. mainマージ・本番デプロイの個別承認を取得する。mainマージが自動公開につながる場合は、デプロイ承認前にmergeしない。
4. 承認後にこの独立PRだけを公開し、匿名プロフィール・共有リンク・QRの回帰確認を行う。

本番DB変更・PR #101の統合・物理バックアップ復元は、このフロントエンド差分の前提ではない。問題時は承認済みの前版へアプリを戻す。DBを戻したりデータを削除したりしない。
