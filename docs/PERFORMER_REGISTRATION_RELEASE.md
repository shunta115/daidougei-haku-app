# パフォーマー事前登録

登録URL: https://daidougei-haku-app.vercel.app/live/register

## 出演者の手順

1. 登録URLを開き、芸名・メールアドレス・パスワードで登録する。登録済みの場合は「ログイン」。
2. 「プロフィールを完成させる」で写真・芸名・ジャンル・自己紹介・活動地域を登録して保存する。SNSや動画、受賞歴は任意。
3. 登録状況に戻り「Stripeで受取設定を始める」へ進む。本名・本人確認書類・振込口座はStripeに入力する。アプリの公開プロフィールには保存しない。
4. アプリに戻るとStripeの状態を再取得する。確認中・追加入力・完了を区別する。途中で閉じても同じアカウントでログインして再開できる。
5. プロフィールと受取設定が完了すると運営の確認待ち。別途申請ボタンを押す必要はない。承認後に公開・LIVE・販売を利用する。

保存済みプロフィールはDBから復元する。未保存の公開用テキストは同じブラウザ・同じアカウントの下書きとして復元する。別端末やブラウザデータ削除後の再開には事前の保存が必要。

既存のfan/organizerアカウントを自動的にperformerへ変更しない。登録用URLで役割が異なる場合は、パフォーマー用のアカウントでログインし直す案内を表示する。

## 運営の手順

1. https://daidougei-haku-app.vercel.app/live で既存のadminアカウントにログインする。
2. 「登録確認」で芸名検索、未承認、登録完了・運営確認待ち、公開中、すべての絞り込みを使う。
3. 写真とプロフィール、Stripe受取設定、承認状態を確認する。
4. 登録完了者の「承認して公開」を押す。停止・削除状態のアカウントはこの一覧から再承認できない。
5. 「公開中」で反映を確認する。イベントの出演者・タイムテーブルへの紐付けは既存のイベント運営画面で別途行う。

Stripeの完了状態は既存のaccount.updated Webhookと、出演者による受取状況の再確認で同期する。運営一覧の「更新」は保存済みのDB状態を再取得する。

## 検証と境界

- 新規登録のperformer役割、確認メールが必要な場合の分岐、ログイン後のダッシュボード、Stripeからの復帰、下書き復元、DB保存失敗、受取設定の認証・所有者チェックを自動テストで確認。
- 390px幅のローカルブラウザで登録・プロフィール・登録状況・運営確認を表示し、横はみ出しなし、主要タップ領域44px以上、入力文字16pxを確認。
- 架空のローカルデータでプロフィール保存・写真処理・承認済み一覧への反映を確認。Productionの認証付き新規登録・Storage書き込み・承認は実行していない。
- 本番の公開RESTで必要なプロフィール列とメール新規登録の有効性を確認。管理者権限での本番RLS・Storage検証は今回の実行環境では未実施。
- 本番DBのスキーマ・既存データ、Stripe/Webhook/LiveKitの設定、Secretsは変更しない。migration追加・適用は不要。
- 投げ銭・Direct Charge・application fee・決済Webhookの処理は変更しない。
- 認証イベント内のDBアクセスをReact effectへ移し、Supabaseの認証ロックによる停止を防ぐ。既存のアクティビティ更新は維持。

実装確認の参照: [Supabaseの認証イベント](https://supabase.com/docs/reference/javascript/auth-onauthstatechange)、[Stripeの登録・本人確認状態](https://docs.stripe.com/connect/handling-api-verification)。

## 招待送付前の実機確認

1. iPhone Safariで新しい出演者アカウントを1件登録し、写真保存、ログアウト後の再開、Stripeから戻った後の状態を確認する。
2. 実際の出演者向け受取登録がStripeの本番モードにつながることを確認する。Sandboxの成功は本番受取登録の確認とは別。既存のキーやConnected Accountを自動的に置換しない。
3. 運営アカウントでその登録者を確認・承認し、匿名の「探す」で公開プロフィールを確認する。確認済みのLIVE・投げ銭の再テストは不要。

DB上の承認フラグ・役割・Stripe参照列の更新権限については、ローカルmigrationだけでは現在の本番RLSを確定できない。今回の変更では権限を追加・緩和していない。
