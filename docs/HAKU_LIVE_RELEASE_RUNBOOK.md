# HAKU LIVE リリース・実機回帰ランブック

更新日: 2026-10-16

## 目的と合格条件

この手順は、HAKU LIVE のカメラ取得、LiveKit送信、視聴者受信、縦横UI、コメント、ギフトを一つのリリース単位として確認する。自動テストの成功は実機合格の代替にしない。iPhone Safari、Android Chrome、PCブラウザの各欄に実際の端末名、OS/ブラウザ版、時刻、確認者、結果を記録して初めて実機合格とする。

本番公開の必須条件は次のとおり。

- `npm run typecheck`、`npm run test:live`、`npm run test:registration`、`npm run build` がすべて成功する。
- PRのGitHub ActionsとVercel Previewが成功し、差分にStripe/Connect送金、破壊的DB操作、無関係な変更がない。
- 配信者端末と別の視聴者端末を使い、送信側だけでなく受信側の動画フレーム・音声・コメント・ギフト表示を確認する。
- iPhone Safariで前面→背面→前面を10回切り替え、各切り替え後に最低10秒、動画が連続更新する。
- 縦持ちは9:16、横持ちは16:9の表示領域を維持し、引き伸ばし、過度なクロップ、二重映像、大きな黒帯、UI重なりがない。
- カメラまたはマイクを停止してもRoom、コメント、ギフト、視聴者数が継続し、個別に再開できる。

## 1. 自動リリースゲート

```sh
npm ci
npm run typecheck
npm run test:live
npm run test:registration
npm run build
```

`test:live` は、映像の縦横制約、前後カメラ10回切り替え、静止画を成功扱いしない連続フレーム判定、カメラ/マイク停止・再開、30fps回転、単一映像レイヤー、投げ銭安全性を含む。失敗をスキップ、更新、期待値の緩和で隠してはならない。

## 4. コメント・ギフト回帰

1. 端末Bから20件以上コメントし、最新へ自動スクロールする。
2. 端末Aで過去コメントへスワイプし、その間にBから新規投稿する。表示位置が飛ばず「最新コメント」が現れることを確認する。
3. 最新へ戻り、以後の投稿に追従することを確認する。
4. 配信者または登録モデレーターがコメントを削除し、A/B双方から即時消えることを確認する。
5. ユーザーをそのLIVEでミュートし、別LIVEや既存コメントデータを無断変更しないことを確認する。
6. ギフト通知中にも映像フレーム、音声、コメント、操作ボタンが止まらず、演出がLIVE終了ボタンを覆わないことを確認する。

## 5. 長時間・負荷確認

最低30分、可能なら2時間配信し、5分ごとに配信者/視聴者のフレーム更新、音声、Room接続、コメント、視聴者数を確認する。開始時、15分、30分、終了前にブラウザのメモリ、CPU、上り通信、端末温度警告の有無を記録する。フレーム停止、音声消失、再接続ループ、継続的なメモリ増加があれば公開を止める。

## 6. 公開確認とロールバック

1. 承認済みPRだけをmainへ統合し、反映commit SHAを記録する。
2. Vercel Productionのdeployment ID、source commit、Productionドメインの割当を一致させる。
3. 本番で非決済のスモークテストを行い、実機マトリクスの最重要項目を再確認する。
4. P0症状（横長固定、過度なズーム、映像静止、二重映像、操作不能）またはコメント/ギフト停止を一つでも検出したら、新規DB操作をせず直前の正常なVercel deploymentへロールバックする。
5. DB/RLSを含むPRは、アプリだけ先行公開しない。後方互換性と適用順序をレビューし、明示承認後にマイグレーションとアプリを同じリリース枠で扱う。
