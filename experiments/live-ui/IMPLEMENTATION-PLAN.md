## ぼかし・余白の調査

- 映像要素と既存Canvas処理にはblurフィルターがない。コメント・操作部のbackdrop-filterは背後の矩形をぼかすため、LIVE上のUIから除去した。
- 現在の既存送信経路には720×1280/1280×720のCanvas全画角合成がある。再サンプリングと内部黒帯はあり得る。今回、カメラ取得・Canvas・エンコード設定を無条件には変更していない。
- LiveKitのmediaStreamTrackはprocessor有効時に加工後トラックを返す。これを原カメラ取得と誤表示しないよう、getSourceTrackSettings、送信入力、実SenderStats、表示寸法を別々に診断する。
- 部分的なモザイクの原因は実機で未確定。原カメラ、送信入力、エンコード寸法・帯域制限、表示を比較して判断する。参考画像の加工有無も断定しない。
- containは全画角、coverは利用者が選ぶ表示上のクロップ。カメラや送信トラックは変更しない。

## 自動検証

GitHub quality gateでTypeScript、Vitest、本番buildを実行。独立WebKit workflowは実画面コンポーネントにlocalhost限定の合成映像/APIを接続し、390×844/844×390、コメント0/100/1000件、設定シート、表示モード、操作、小窓、80件上限到達後の新着追従を検証し、JSONとPNGを保存する。実iPhone・実LiveKit・実音声の成功としては扱わない。
