# HAKU LIVE UIリニューアル — 実装計画

## 基準
ユーザー提供の4画面デザイン：縦型視聴／縦型配信／配信前設定／横型視聴。ミニプレイヤーと通知も対象。

## 今回の成果
- `/haku-live-immersive-preview.html` に**独立したUI操作試作**を追加。
- 画面全体に映像領域を固定。コメントは独立スクロール領域に半透明で重ね、件数が増えても映像の高さを変えない。
- 配信方向・画質設定をダイアログに移動。配信者と視聴者を切り替え、コメント入力、フォロー、いいね、ギフト、マイク、カメラ切替、配信終了確認を画面上で操作可能にした。
- **重要：本PRの画面はUI試作のみ。実映像、コメント送信、投げ銭、フォロー、エフェクト、ミニプレイヤー、通知は本番サービスに未接続。** 課金や配信操作は行わない。
- 画像素材・人物写真をコピーせず、実ユーザーデータを使わない。

## 次の実装フェーズ（未実装）
1. mainの既存LiveKit視聴・配信コンポーネントとイベントハンドラを監査し、映像・カメラ・マイク・コメント・投げ銭・フォローの既存APIに接続。
2. 映像のアスペクト比は実トラックから判定し、9:16/16:9に適切にフィット。無理なトリミング禁止。
3. 配信方向の選択はLIVE開始前に設定、配信中の変更は既存`switchHostVideoOrientation`等のAPIに接続。端末の回転に自動追従する場合は事前確認。
4. コメントは実データをリアルタイム購読。メッセージが増えても映像は縮小しない。チャットの最大表示数・モデレーション・キーボード/セーフエリアを検証。
5. 横型表示はiOS Safariの画面回転制約に対応。横型LIVEを別ルート/モーダルにして再生できるようにする。
6. ミニプレイヤーは**アプリ内**のルート遷移で維持する仕組みを優先。iPhone Safariでブラウザ外/ホーム画面に常時表示できると約束しない。Picture-in-Pictureの対応範囲は実機検証。
7. 通知は既存Web Pushとユーザーの同意・登録・配信開始イベントを連携。通知許可・iOSホーム画面Webアプリ制約・重複通知防止を実測。デモ通知を実送信しない。
8. 全画面の操作性、VoiceOver、キーボード表示、コメント100/1000件、縦横、低速回線、映像・音声再接続をiPhoneで検証。
9. 新しい独立Previewに実配線したものを公開前にテスト。本番デプロイ・mainマージは個別承認後。

## 変更禁止
本番DB、Stripe、LiveKit配信基盤、SRS PR #98、AWP、main、本番デプロイ。有料サービス契約・外部公開も個別承認制。
